# ADR-001: Keep PostgreSQL Instead of SOW-Specified MySQL

## Status
Approved

## Date
2026-09-17

## Context
The Employee Leave Management SOW (`docs/Employee_Leave_Management_SOW_NextJS_NodeJS.pdf`, v1.1) specifies MySQL as "the only database in scope" (SOW §3, §6, §11). However, the project was already scaffolded during `/int-project-setup` with PostgreSQL + TypeORM, before the BRD/SOW was ingested. This created a direct conflict between the BRD-stated database technology and the already-established architecture.

## Decision
Keep **PostgreSQL** as the project's database engine, accessed via TypeORM. This is confirmed by the project owner as an approved deviation from the SOW's database specification. All specs, plans, entity models, and migrations for this project target PostgreSQL, not MySQL.

## Consequences
- **Positive:** No backend rework needed; avoids re-scaffolding the already-built and verified `backend/` TypeORM/PostgreSQL setup.
- **Negative / Risks:** Deviates from the signed-off SOW's stated technology; if the SOW is a binding client contract, this deviation should be communicated back to the client/project sponsor and reflected in a SOW amendment or documented exception.

## Compliance & Constitution Impact
- Updates `.ai-context/BRD.md` — "Approved Technology Deviation" section records this decision.
- Updates `.ai-context/architecture.md` / `.ai-context/constitution.md` — database technology remains PostgreSQL (no change needed, already so from project setup).
